# EVALUATION_RUBRIC — IMP-606 lexical/full-text retrieval

This rubric is designed for an independent evaluator that has the exact candidate, source-derived packet, and required runtime/evidence artifacts but does not have the implementation conversation or implementer reasoning transcript.

## Adversarial checks

1. Seed an unauthorized room/guild with a unique token and an authorized scope with none; query the token and inspect not just returned hits but result counts, rank features, snippets, errors, logs, cache keys and repeatable timing where practical.
2. Put the same lexical token in authorized and unauthorized records with different ranks to detect whether unauthorized rows participate in ranking before filtering.
3. Exercise `since`/`until` at exact timestamp boundaries and query current versus superseded fact versions.
4. Delete/redact a source immediately before search in the same process/transaction boundary; search again after restart and after full rebuild.
5. Inject failure between authoritative write and derived-index update to prove rollback/orphan behavior; repeat around correction/supersession.
6. Verify assistant output eligibility follows delivery/output authority rather than indexing every generated segment regardless of delivery/current-context policy.
7. Compare NFC-equivalent strings, compatibility-width characters, case variants, punctuation, aliases, kana/kanji/han, Simplified/Traditional Chinese, and mixed ASCII+CJK without altering source evidence.
8. Query CJK under an implementation that lacks passing CJK analyzer evidence; require explicit unsupported capability rather than a confident empty result.
9. Perturb/scale scores from one profile in a test double or fixture to expose any direct cross-profile raw-score addition.
10. Rebuild the index twice from the same authoritative snapshot and compare document identities, source links, analyzer metadata and query results.
11. Re-run the same frozen multilingual benchmark at the same candidate/dataset/analyzer identity; investigate unexplained semantic result drift.
12. Compare base/candidate test fixtures, dataset judgments, policy files, thresholds and scripts for deletions/relaxations or candidate-favoring edits.
13. Confirm migration v1-v8 bytes/checksums against base; a “harmless” historical migration edit is a required failure.
14. Confirm performance-v2 measured commit `9afc7207...` and evidence/docs commit `1b0d3b50...` are not rewritten into the IMP-606 candidate identity or used as retrieval threshold approval.
15. Disable `fulltextRetrieval` and prove prior runtime behavior is restored; verify vector/graph/on-demand/relationship/remote flags stay unaffected.
16. Request vector/graph modes and unsupported language capability to prove explicit typed gating survives the lexical implementation.
17. Search logs/report output for raw user content or protected identifiers that should have been content-minimized/redacted.
18. Inspect GitHub/local history for unauthorized remote publication or evidence commits pushed without explicit authority.

## Evidence hierarchy

Resolve disagreement in this order:

1. Explicit user instruction and current publication authority.
2. Runtime IMP-606 `Plan.md` at its recorded attachment/hash identity.
3. Fresh direct repository/local checkout reads at the exact candidate SHA, including executable tests/runtime behavior.
4. Repository-owned normative contracts/policy/backlog and acceptance evidence at their exact recorded identities.
5. Exact candidate runtime/benchmark artifacts, manifests, dataset/analyzer/index digests, commands and independently reproduced results.
6. `COMPILED_SPEC.md`, `TASK_SKILL.md`, `REPO_CONTEXT.md` and role reports derived from those sources.
7. Historical seed/decision logs only for context at their recorded commits.
8. Code search/discovery output only after direct-read confirmation.
9. Generic assumptions/best practices are not acceptance evidence.

When historical evidence was generated at an older commit, preserve that historical identity rather than replacing it with the current candidate. A newer status document does not automatically supersede a more specific evidence record; classify and reconcile the evidence source explicitly.

## Final decision rule

- **PASS:** every required criterion in this rubric passes for the exact candidate and both independent evaluation paths pass.
- **FAIL:** one or more required criteria fail. A required failure cannot be averaged away by stronger results elsewhere.
- **INCOMPLETE:** no required failure is proven, but one or more required capabilities, commands, artifacts, runtime checks, data slices, or independent evaluations are missing/unexecuted/incompatible.

There is **no majority vote** and no score averaging that can erase a required failure. Missing evidence is never a pass. A language capability may remain explicitly unsupported while IMP-606 still produces a valid measured lexical baseline if all plan completion conditions and capability-truth requirements are satisfied; false advertisement is a failure.
